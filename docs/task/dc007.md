## 2. 測試編排與版本

Root 管理 Git、品質指令與 server；normal production 使用未占用 loopback 3280，停止後才建 Pages／3281，不同時覆寫 `.next`。先核環境、工具及實際 tiny 預檢，保存 source 範圍／SHA；所有長指令使用 `scripts/run-with-evidence.py` 真正等待並保存 OS exits。正式效能採樣時停止其他 browser／PDF／axe／build 工作。

最終基準：`npm ci`、必要 `npx next typegen`、`npx tsc --noEmit`、`npm run lint`、`npm test`、`npm run build`、`npm run build:pages`。不因文件補記重跑無關 App；若 App 修正，依實際影響及原工作包選重驗，保留原失敗／工具版本。不得用 fingerprint 單獨判定語意相同。

## 5. 失敗政策與交付

狀態僅PENDING/PASS/FAIL/BLOCKED/N/A；N/A須具適用性理由，外部缺環境或真人證據使用BLOCKED。每項保存Test ID、procedure/command、environment、expected、actual、OS exit（人工為N/A並說明）、evidence及限制。初始皆PENDING。

失敗先修再重驗；原始FAIL不改寫，未修缺陷列Known Issues。HEAD取消要有精確觀測證據與限定判讀，不以所有HEAD或ERR_ABORTED一律忽略，也不把未知status補成200。阻擋FAIL或外部Required BLOCKED存在時，不能宣稱完整發布驗收通過。仍完成可獨立工作、提交真結果與待辦PR，不隱藏缺口。

完成後commit/push分支、建立base main PR，核對精確head CI與實際artifact。後發遠端事件更新同PR說明，避免自記SHA循環commit。沒有本輪人工合併／部署授權；不發布功能分支，不改DNS。正式索引、法律政策及公司新品牌資產遷移各自核准，不由DC-007測試結果推定。
