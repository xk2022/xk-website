## 3. 三個設計方向

| 項目 | Heritage 懷舊復古 | Modern 現代專業 | Luxury 奢華精品 |
| --- | --- | --- | --- |
| 定位 | 經典與傳承 | 專業與創新 | 品味與非凡 |
| 配色方向 | 米白、焦糖、墨綠 | 現有 XK 深藍、亮藍、白 | 黑、香檳金、象牙白 |
| 字體方向 | 復古襯線、易讀正文 | 現代無襯線 | 優雅襯線、清楚正文 |
| 版面 | 復古雜誌／刊物 | 企業模組化 | 精品畫冊／編輯式排版 |
| 互動 | 柔和淡入 | 流暢精準 | 節制、舒緩的電影感 |
| 主要價值 | 品牌故事與溫度 | 解決營運與技術問題 | 品牌價值與精緻體驗 |
| 適合情境 | 傳統食品、咖啡、老店、文創 | 科技、製造、物流、企業服務 | 燕窩禮品、珠寶、室內設計、高端餐飲 |
| 提案例示 | 盛豐洋、蕋咖啡 | 宏能興業、元廣科技 | 宏家燕窩、一森室內設計 |

例示為客群或提案方向，非已成交、客戶授權或正式交付聲明。色值、字型授權、素材與 Logo 變體依公司規範及實際核准；先保護既有正式識別。

設計差異採 Level 3：獨立首屏構圖、服務表達、作品編排、節奏、版型與視覺敘事。Level 1 只換色、Level 2 換色／字型／元件不足以達成展示目的。動畫遵守 Reduced Motion，對比、可讀性與操作可及性不可因風格降低。

## 4. 網站入口與部署

| 版本 | 開發／初期預覽路徑 | 未來候選正式入口 |
| --- | --- | --- |
| Modern | / | www.xplorekaleidoscope.com |
| Heritage | /heritage/ | heritage.xplorekaleidoscope.com |
| Luxury | /luxury/ | luxury.xplorekaleidoscope.com |

- Modern 為預設正式官網；不強制進站先選風格。
- 主導覽加入「探索設計風格」，首頁設三張設計預覽卡，支援直接分享對應網址與回到 Modern。
- 三套視覺使用同一 Repo；不另建三個 Repo，不在規劃階段變更 DNS 或部署。
- 初期使用路徑、Next.js App Router 與現有靜態 Pages export；子網域候選僅為未來方向。須確認平台是否支援目標部署方式，取得 DNS／憑證／部署授權後獨立驗收，不假定一個 Pages 設定即可綁定多入口。
- SEO 以 Modern 正式內容為主；替代入口的 canonical／索引規則需逐頁決策，避免重複內容競爭。在正式發布 gate 完成前保留既有 SEO 保護，不開放索引或修改 Sitemap。

## 5. 共用架構

一個資料來源，多套展示層：

- 共用品牌名稱、核准 Logo、品牌故事與服務設定。
- 共用作品資料、狀態與展示權利限制；各風格依相關情境選擇呈現順序。
- 共用方案試算、詢價流程及聯絡資料，不重複計價邏輯。
- 各風格獨立 semantic design tokens、layout、視覺元件及素材。
- 保持 Next.js、React、TypeScript、Tailwind、既有 Vercel 相容 build 與 GitHub Pages 靜態 build，不新增 Backend 或 DB。
- 既有 /contact 只準備 Email 草稿；/quotation 是參考試算，不視為直接收件、訂單或正式報價。維持現有資料、儲存及發布保護。

## 7. 商業應用與衡量

- 客戶訪談與提案：讓客戶直接選擇設計方向，而非先閱讀長篇規格。
- 累積可重用的設計系統，降低 LP、BRAND 專案的重複設計工時。
- 以風格對應產業案例與服務價值，支援客製化討論。
- 未來經隱私及資料方案核准，可評估各風格入口流量、作品點擊、試算使用、有效詢價與實際成交；本輪不新增 Analytics／追蹤。
